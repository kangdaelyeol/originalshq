# 리드 매니저·CMIP 피드백 요구사항

- 받은 날: 2026-11-06
- 범위: 리드 매니저(`src/screens/xtool-lead-manager`), CMIP(`src/screens/cmip`), 동기화 함수(`functions-xtool`, `functions-cmip`)
- 이 문서의 쓰임: 원문에서 요구사항을 뽑아 체크리스트로 관리한다. 하나를 끝낼 때마다 체크하고, 그 요구사항의 "변경 기록"에 무엇을 어떻게 바꿨는지와 근거를 적는다.
- 요청마다 해석과 바꾼 점만 빠르게 보려면 원문 바로 아래 "원문 요구사항 · 해석 · 바꾼 점" 표를 본다.

## 표기

- `[ ]` 할 일, `[x]` 끝남, `[-]` 하지 않기로 함(이유를 적는다)
- 판정: **맞음** / **일부 맞음** / **다름** — 원문의 지적이 코드와 맞는지
- 종류: **개선**(지금 데이터로 고침) / **수집**(새 데이터가 먼저 필요) / **신규**(새 기능)
- 숫자(47명 중 38명, 612만 원, 60.6% 등)는 운영 DB를 보지 않아 확인하지 않았다. 그런 숫자가 나오는 원리만 코드로 확인했다.

## 원문

> **1. 신규 인입 피드 화면**
> 먼데이 쓸 때는 신규 인입 고객 항목과 상담 메모를 스크롤만으로 쭉 읽을 수 있었는데, 지금은 고객별로 클릭해야 내용이 보여서 흐름이 끊깁니다. 소재 품질이나 렌탈 오해 같은 신호가 이 원문에서 나오기 때문에, 클릭 없이 읽히는 표 형태 화면이 하나 있으면 좋겠습니다.
>
> - 열: 인입 시각 / 보드(제품) / 이름·연락처 / 유입(매체·캠페인·소재명 utm_content) / 문의 원문 전체 / 최근 상담 메모 미리보기(2~3줄, 마우스 올리면 전체) / 콜백 단계·진성 등급·오기입 / 담당자 / 첫 콜까지 걸린 시간
> - 필터: 오늘·어제·이번 주, 보드별
> - 소재별 묶어 보기 토글: 같은 소재로 들어온 리드의 원문과 메모를 한 덩어리로 읽을 수 있게
> - 키워드 하이라이트: 렌탈, 할부, 가격, 원거리, 학교·기관, 견적 등은 색이나 태그로 표시
>
> **2. 주간 매체 성과표**
> 지금은 광고비는 CMIP에, 유효 리드·오기입·방문체험은 Lead manager에 나뉘어 있어서 매체 판단을 하려면 두 화면을 오가며 손으로 계산해야 합니다. utm_campaign 기준으로 두 데이터를 붙인 표 하나를 부탁드립니다.
>
> - 행: 매체 > 캠페인 > 소재 (펼침)
> - 열: 광고비 / CRM 유효 리드 / 유효 리드당 비용 / 오기입률 / 진성률(A·B1·B2) / 방문체험 예약률 / 결제 전환(유입월 기준)
> - 기준선 표시: 유효 리드당 13만 원, 오기입률 30%
> - 결제는 리드타임이 길어서(중앙값 22일) 유입월 코호트로 30·60·90일 숙성 값을 따로 보여 주시면 좋겠습니다
>
> 그리고 보다가 숫자가 이상해 보이는 부분이 있어서 같이 공유드립니다. 확인 부탁드려요.
>
> - 전체 요약 Conversions/CPA: 매체별로 다른 이벤트가 합쳐져 Meta CPA가 1.8만 원 수준으로 나옵니다. 실제 문의 CPA는 7~10만 원대라, 문의(CRM 유효 리드) 기준으로 통일이 필요해 보입니다
> - 기획전/방문체험 캠페인: 전환 856건, CPA 309원으로 잡혀 있어 랜딩뷰 같은 이벤트가 들어간 것 같습니다
> - 네이버 브랜드검색: 광고비 0원으로 잡혀 네이버 ROAS가 높게 나옵니다. 정액 계약 비용을 일할로 넣어 주시면 됩니다.
> - 퍼널 통계 유입 경로: 구매 47명 중 38명(약 8,095만 원)이 '미기록'입니다. 상담 등록 시 유입경로 필수값 처리나 전화번호로 GA4·카페24 역매칭이 가능할지 궁금합니다
> - 코호트 ROAS: 상단 기간 필터가 코호트 표에도 적용되는 것 같습니다(10월 코호트 광고비 612만 원). UTM 광고 0.0% 표기도 확인 부탁드립니다
> - 카페24 환불율 60.6%: 온라인 주문 취소 후 오프라인 결제로 넘어간 건이면 매출이 중복될 수 있어 확인이 필요합니다
> - 퍼널 통계 구매 기준이 '온라인'인데 하단 안내는 오프라인 포함으로 되어 있어서, 기본값을 '통합'으로 맞추면 좋겠습니다
> - 판매 통계: 장비·소모품·AS가 같은 순위에 섞여 있어 카테고리 구분이 있으면 좋겠습니다

  - 8·9(서버, 격리 에뮬레이터 demo-xl): 예전 코드(원본에서 읽기)와 새 코드(묶음에서 읽기)의 응답이 전체·1일·30일·92일·미래 모두 바이트까지 같음. 마지막 묶음을 지워도 30일은 앞 묶음만 읽어 그대로·전체는 원본으로 대신, 줄 모양 판이 다르면 묶음을 안 읽음, 그대로면 다시 안 씀·바뀌면 새 판(전 판 남기고 전전 판 지움), 유선이 먼저 적힌 번호도 휴대폰이 대표 번호. 고객 목록은 예전 코드가 쓴 것을 새 코드가, 새 코드가 쓴 것을 예전 코드가 읽어도 고객 문서마다 읽은 것과 같음.
- 배포(6~10): 서버 — 묶음을 쓰는 동기화·재생성 함수와 읽는 getMondayLeadFeed·listMondayCustomers. 함수만 먼저 올라가고 묶음이 아직 없으면 예전처럼 원본에서 읽으니 순서 걱정은 없다(다음 예약 동기화나 재생성 한 번 뒤부터 묶음에서 읽음). 프런트는 푸시.
  - 리드 줄에 칸을 더할 때(다음 주 C1~C3): 서버 `MondayLeadFeedRow`(types.ts) + `buildLeadFeed`(lead-feed.ts) + `LEAD_FEED_ROW_VERSION` 올리기, 화면 `LEAD_COLUMNS`에 칸 하나.
